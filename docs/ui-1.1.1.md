# 1.1.1 介面與操作

原生 Tk/ttk 淺色下載工作台，不增加瀏覽器介面或網頁服務依賴。

## 設計

- 米白灰背景、白色卡片、深綠主要動作。警告及錯誤皆有文字，不僅靠顏色。
- Microsoft JhengHei UI 中文字型、統一間距與有名稱的按鈕。
- 左側清單／模型／目的地，右側總覽與四模型進度，下方執行紀錄。
- 保留鍵盤焦點、垂直捲動及小視窗焦點可見性，不使用裝飾動畫。
- 狀態直接讀取批次執行器，不顯示推估的成功數或假完成。

使用 ui-ux-pro-max 的設計查詢及通用可讀性、焦點、回饋規則。查詢中的行銷頁區塊與 OLED 深色風格不適用此 Windows 桌面工具，因此僅採用操作狀態、語義色彩與清楚焦點建議，採淺色原生介面。

## 操作改善

- 有效選項齊備才允許開始，下載期間鎖定輸入，避免看起來能更改執行中的批次。
- 停止並保存通知工作執行緒，保留視窗；關閉仍等工作執行緒完成保存。
- 續跑帶入原批次模型與目的地，開啟資料夾不再指向之前的選項。
- 全部成功、有失敗、登入等待及停止保存有不同文字。
- 日誌每次最多處理 100 筆，畫面保留約 1500 行，完整檔案日誌照常保存。

## 驗證

58 項回歸測試通過，包含單窗登入繼續、停止保留視窗、下載期間選項鎖定、續跑目的地、未完成批次摘要。以模擬資料檢查 1120×840 與 900×620 視窗截圖；預覽不向網站請求。畫面為淺色模式，未宣稱深色模式或完整螢幕閱讀器支援。

UI 使用相同批次執行器、5 秒間隔與等待上限 1。1.1.0 的 Charles2.4 實站結果屬下載器驗證；1.1.1 未為介面改動重跑正式清單。

另外新增 `tests/check_batch_timeout.py` 並通過：四個獨立 Chrome、真正 90 秒逾時、95 秒遲到結果、不誤存舊回應、有限補抓、共用冷卻與 5 秒提交間隔。11/12 成功，唯一失敗為測試刻意永久回傳 Try Again 的項目，符合預期。
