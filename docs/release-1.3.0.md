# 1.3.0：AI 控制與多清單任務

新增 start、status、stop、resume、retry、continue 控制命令，AI 不需操作檔案選擇視窗。各命令輸出 JSON 回覆；GUI 顯示任務所屬清單、各模型進度、登入等待、冷卻及最終失敗列表。

## 已確認的行為

- 所有清單在開始前驗證來源、ticker、模型及目的地寫入能力，保存內容快照。
- 各模型按清單順序推進，沿用同一個共用排程器，等待上限 1、提交至少相隔 5 秒。
- 每份清單的每模型在既有補抓後自動額外重試一次，仍失敗則記錄並前進；登入等待不消耗額外重試次數。
- 登入問題仍只恢復及暫停該模型。該模型等待時，其餘模型可以繼續後面的清單。
- AI 命令與 GUI 為不同程序；短暫命令退出後 GUI 繼續下載。GUI 仍可手動停止並保存、登入後繼續或重試失敗。
- 每次變更使用請求 ID，操作前保存紀錄；重送不會重播已處理或結果不確定的操作。任務 ID 對應固定清單快照。
- 換清單、補抓與明確續跑保留冷卻。GUI 意外中斷後重啟先冷卻 120 秒，不假定伺服器已取消原請求。
- GUI 清單讀取失敗時清除舊 ticker，避免錯用上一份清單。
- 維持所有原有檔名與目錄格式，沒有建立新每日排程。

## 驗證

- 82 項單元測試，包含重試上限、停止續跑、模型獨立推進、請求防重播、離線辨識及舊功能回歸。
- 本機五個獨立 Chrome、兩份清單：Gamma 等待登入時其餘四模型完成兩份；恢復 Gamma 後 10/10 完成，Table 存放及內容驗證通過。測試縮短提交間隔，未更改正式參數。
- 獨立 GUI／命令程序：啟動、查詢、重複請求、命令程序退出後繼續下載及最後總結通過。使用模擬下載器，沒有實站請求。
- 有一次控制確認在 30 秒期限內未返回，後續單次重跑及連續五次重跑均通過，未重現原因。逾時一律回報 unknown，需查詢原任務或使用同一請求 ID 重送；已測試延遲確認後不重複執行。
- 打包版元件自我檢查與 AI 離線查詢的 JSON 輸出通過。

使用方法及接續規則見 [AI 操作說明](agent-interface.md)。未進行新版本的實站整批下載，也未驗證電腦睡眠或未登入桌面時的排程啟動。
